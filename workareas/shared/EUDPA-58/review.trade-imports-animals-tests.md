# Repository Review: trade-imports-animals-tests

**PR:** #94
**Commit:** 7fcd979
**Files Changed:** 26

## Summary

Adds a 30-operator Mongo seed and rewrites the party-selection and persistence specs to assert against real address-book data instead of hardcoded mock names, plus five new address-book page objects and two new address-book feature specs. The data work is meticulous — every seed-derived expectation across all the specs was verified correct against the generator's index arithmetic. The problem is the new page objects: they model an "operator" address book that no repo in this epic delivers.

## Positive Observations

- Every name, operator type, address, country, approval number and transporter category asserted in the rewritten specs checks out against `seeds/mongodb/30-operators-seed.js`.
- The seed matches the operators service's M1 contract exactly — database, collection, camelCase fields, `_class` FQCN, enum values, and a `crn`/`organisationId` that match the sign-in page's default.
- The `schemaVersion` `'1'` to `'2'` change tracks the backend bump correctly.
- The seed file is picked up automatically by the stack's init-script staging; no wiring needed.

## Test Coverage

- **Coverage added:** two new address-book feature specs and an all-operators spec, plus per-party selection coverage across seven party pages.
- **Coverage that is not what it looks like:** both submit legs of the address-book journey spec end on `toHaveURL(pages.declaration.expectedUrl)`, but `/declaration` is also the URL after a *rejected* submit — so the M1.5 guard tests pass whether or not the notification submits. The type-scoping assertions on four party pages spot-check three rows and make no negative assertion, so the headline "filtered by operatorType" behaviour would still pass if the page listed all 30 operators.
- **Flakiness:** the pagination test reads the unfiltered list under `fullyParallel: true` while sibling specs create operators against the same CRN; CI does not reseed, so left-behind operators accumulate.

## Risk Assessment

**Overall Risk:** Medium
**Rationale:** Test-only repo, so no production blast radius — but the page objects bind to a UI that does not exist, and several new assertions are green by construction rather than by behaviour.
