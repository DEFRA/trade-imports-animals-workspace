# Repository Review: trade-imports-ins-frontend

**PR:** #1
**Commit:** e99a31a
**Files Changed:** 87

## Summary

A brand-new Node/hapi GOV.UK frontend for the address book, forked from the CDP node-frontend template with the Defra ID auth module ported across from `trade-imports-animals-frontend`. It delivers list/add/view/edit/delete against the address-book service with org scoping taken from the signed-in user's relationship id. This carries the largest concentration of risk in the epic: 9 Critical and 77 Major findings across 87 files. The auth port lost two fixes the source repo carries, the outbound HTTP client does not encode path segments, the success banner renders user input as raw HTML, and there is no CSRF protection anywhere in the service.

## Positive Observations

- The identity-header contract with the backend is correct — header name, query params and the `ValidationProblem.errors` camelCase keys all line up with `OperatorController` and `IdentityHeaderFilter`.
- `orgId` is always taken from `request.auth.credentials`, never from the payload.
- Delete is POST-only behind a proper GDS warning-button confirmation page; no destructive GET.
- Route ordering is right (`/address-book/add` literal wins over `/address-book/{id}`), and `health` correctly opts out of the default session auth.
- Joi payload validation whitelists fields, so unknown-key rejection cannot be bypassed.
- Plugin registration order (sessionCache to Cookie/Bell to auth to router) is correct.

## Test Coverage

- **Unit tests:** every controller has a test file and the happy paths are covered, but error branches are systematically untested — the 404 and 500 legs of add/edit/delete, the backend-400 to `mapApiErrorsToFormErrors` re-render that the whole validation UX depends on, and `countries-client.js` has no test file at all. Several assertions cannot fail (`expect(result).not.toContain('operator')` against markup that never contains it).
- **Security-critical gaps:** no test anywhere injects an unauthenticated request against a protected route, so removing `server.auth.default('session')` would leave the suite green. `verify-token.test.js` never makes the JWT verifier return false, so the module's single most important behaviour — rejecting an invalid signature — is unverified. `get-sign-out-url.test.js` was rewritten to assert the regressed output, which would block the fix.
- **Dead test helpers:** `mock-auth-config.js` and `mock-oidc-config.js` have zero imports repo-wide.

## Risk Assessment

**Overall Risk:** High
**Rationale:** Two independent stored-XSS routes into an unescaped notification banner, an open redirect, secrets in URL query parameters, unencoded path segments proxied to the backend host, sign-out that does not terminate the session, and no CSRF on three cookie-authenticated state-changing POSTs.
