# Repository Review: trade-imports-animals-workspace

**PR:** #42
**Commit:** b19391e
**Files Changed:** 87

## Summary

Wires the two new services into the workspace — repo map, Makefile, stack compose files and dev overlay — and commits the EUDPA-58 handover package under `workareas/shared/`. Of the 87 files, 73 are a vendored M0 source snapshot of the address-book service; those were reviewed as a snapshot artifact rather than as production code, and are a faithful package-renamed copy with no secrets and no licence problem. The live wiring has one config defect that breaks the feature in the stack, and the wiring is only half-done: `run-stack.sh`, `setup.sh` and the `tim` repo registry were not extended.

## Positive Observations

- `dev.compose.yml` is clean — build targets, bind-mount paths, platform pin and healthcheck shapes all match the established Java and Node siblings, and both new Dockerfiles really do have the stages it targets.
- Committing to `workareas/shared/` is the sanctioned review-handoff exception in the workspace `.gitignore`, so the location is right.
- `api-contract-v2.yaml` in the handover is the *correct* contract — camelCase, `Trade-Imports-Organisation-Id`, derived `deleted` boolean. The drifted document is the one inside the address-book repo. The handover carried the right contract; the service never adopted it.
- `backlog-v2.json` and `conflicts-v2.json` are internally consistent: 33 increments with a valid topological order, 30 rulings with none open, and every cross-reference resolving.
- `design-v2.md` matches shipped reality section by section.

## Test Coverage

Not applicable — this repo carries no test suite of its own. The relevant gap is that nothing verifies the stack wiring: no check catches `run-stack.sh` and the compose files disagreeing about which services exist.

## Risk Assessment

**Overall Risk:** Medium
**Rationale:** The backend cannot reach the address book in the stack as configured, `-b <branch>` silently ignores both new services (breaking the cross-repo branch-parity rule), and `make setup` never clones them. `HANDOVER.md` is also false at commit time — it says the INS frontend does not exist and M1/M2 are not started, in the same PR that wires the frontend in.
