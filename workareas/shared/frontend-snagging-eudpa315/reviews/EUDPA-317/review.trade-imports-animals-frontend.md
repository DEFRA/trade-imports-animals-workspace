## The headline concern: unscoped mutations

Five independent file reviewers converged on the same issue from different files, and the consistency pass confirmed it with cross-repo evidence.

Removing `isKnownJourney` leaves **no per-user or per-organisation check on any mutating action**. `amendJourney`, `cancelAmendJourney`, `copyJourney` and `softDeleteJourney` now load by `journeyId` alone; `routeOptions` in `shared/kit.js` is empty; `organisationId` feeds audit fields only. Real-mode `load` and `list` are already unscoped. And critically, **no peer repo compensates** — the backend endpoints these four operations hit carry no org or user scoping in this diff or on main. The change therefore converts a weak client-side breadcrumb into no barrier at all, rather than relocating enforcement to a better layer.

The rewritten `engine/journey.test.js` inverts every negative assertion that used to pin this ("Should soft-delete a journey this session never opened"), so the suite now certifies the behaviour as intended. That reads as a deliberate design decision — but nothing anywhere pins a replacement authorisation boundary, and it widens the standing unscoped-listing exposure from read to write.

Two mitigations worth weighing:

- The old guard was already bypassable: `currentJourney` auto-registered any loadable reference, so an attacker needed one extra request. This makes an existing hole direct rather than creating a new one.
- The removal is **genuinely entangled with EUDPA-317, not merely co-located**. The new tests-repo spec "copies a submitted notification straight from its dashboard row" fails without it, because in real mode the dashboard lists rows the session never adopted.

The call for the merge decision is whether that entanglement justifies landing an unscoped-mutation change under a `Lowest`-priority snagging ticket, or whether EUDPA-325 should land as its own PR with its own authorisation decision recorded.

## Positive Observations

- **The `actionUnavailable` mechanism is well built.** `parseActionUnavailable` is a closed `Set`-based allowlist, so a crafted query value cannot reach the template's dynamic index and 500 the dashboard. All four action names have `title` copy in both `copy.en.js` and `copy.cy.js`, so no locale can hit an undefined-index render failure, and `copy-parity.test.js` holds.
- **Dead-code removal is thorough.** `copySucceeded` and `?copied=1` have zero residual references anywhere in `src/` or `prototypes/`, and the orphaned `copy.successTitle/successBody` keys went with them in both locales.
- **Two removed ternaries were genuinely dead branches**, not behaviour changes — both stub and real adapters either return a marshalled record or throw, so `restored`/`deleted` could never be falsy.
- **The engine test rewrite is stylistically better**, dropping `vi.fn()` + `toHaveBeenCalledWith` for behaviour-level assertions against the real stub store.
- **`listed-row-actions.test.js` is a well-chosen new test**, binding the real records adapter (not the stub) because the stub's list filters by the session breadcrumb and so could never render the unadopted row the whole class is about.
- The `COPYABLE_STATUSES` triple exactly matches the backend's `isCopyable` and the dashboard's own row-action rules, and correctly excludes DELETED.

## Test Coverage

- **Unit tests:** Mixed. The new `template.test.js` and `listed-row-actions.test.js` are genuine additions, and the `actionUnavailable` allowlist is pinned accept-and-reject. But the rewrite dropped every session-scoping negative assertion across three files without replacement (items 4, 9, 17), `cancelAmendJourney` and `softDeleteJourney` lost their only negatives (item 5), and `COPYABLE_STATUSES` is exercised only for DRAFT — not the SUBMITTED case AC 1 names (item 3).
- **Integration/E2E:** Not exercised here for EUDPA-317; all copy-contract proof lives in the backend IT and the tests repo.

## Risk Assessment

**Overall Risk:** High
**Rationale:** The EUDPA-317 doc note is trivially safe, but the bundled EUDPA-325 branch removes the last client-side barrier to mutating any notification by reference with no compensating server-side scoping in any repo in scope.
