h2. Snag as reported

Copy as new CSS is off

h2. Diagnosis

"Copy as new" on the notification dashboard renders in the browser's default serif (Times) while every action next to it renders in GDS Transport. The cause is a single conflicting declaration in the custom stylesheet.

h3. Where the element is

{{frontend:src/server/app/sets/live-animals/journeys/linear/features/dashboard/template.njk:91-106}} renders each summary-card action two ways. Actions carrying an {{href}} render as {{<a class="govuk-link">}}; actions carrying a {{postAction}} render as {{<button type="submit" class="govuk-link app-link-button">}} inside a {{<form class="app-form-inline">}} (CSRF crumb and idempotency key must be POSTed, so it cannot be an anchor).

{{frontend:src/server/app/sets/live-animals/journeys/linear/features/dashboard/view-model/row/actions.js:19-24}} gives the copy action a {{postAction}}, so on a DRAFT row "Copy as new" is the ONLY {{<button>}} among Resume / Delete anchors — it is visibly the odd one out, which is exactly what "CSS is off" describes. On a SUBMITTED row "Amend" is a button too, so it is affected identically.

h3. Root cause — cascade conflict on font-family

{{frontend:src/client/stylesheets/core/_main.scss:16}} declares {{font-family: inherit}} on {{.app-link-button}}. govuk-frontend 6.4.0 declares {{font-family: GDS Transport, arial, sans-serif}} on {{.govuk-link, a}}. Both selectors are specificity 0-1-0, so source order decides. Verified in the built bundle {{frontend:.public/stylesheets/application.1ee130c.min.css}}:

* byte 941 -> {{.govuk-link,a\{font-family:GDS Transport,arial,sans-serif;...\}}}
* byte 1080 -> the same rule again
* byte 137469 -> {{.app-link-button\{background:none;border:none;padding:0;cursor:pointer;font-size:inherit;font-family:inherit;font-weight:inherit;display:inline;vertical-align:baseline;line-height:inherit;color:var(--govuk-link-colour,#1a65a6)\}}}

{{.app-link-button}} is emitted last (application.scss {{@use}} order: {{govuk-frontend}} then {{variables}}/{{helpers}}/{{core}}), so {{font-family: inherit}} wins on the {{<button>}} and defeats {{.govuk-link}}.

h3. Why inherit resolves to serif

govuk-frontend 6.4.0 sets font-family per component class only — there is no global rule to inherit from. Proof: {{grep -o "body\{[^\}]*\}"}} on the built bundle returns exactly {{body\{margin:0;background-color:var(--govuk-body-background-colour,#fff)\}}}, and {{.govuk-template}} emits only background-colour / text-size-adjust / scroll-padding / overflow. The full inventory of {{font-family:GDS Transport}} rules in the bundle (53 of them, captured at {{workareas/shared/frontend-snagging-eudpa315/gdsfont.txt}}) contains {{.govuk-summary-card__title}} but NOT {{.govuk-summary-card}}, {{.govuk-summary-card__title-wrapper}}, {{.govuk-summary-card__actions}} or {{.govuk-summary-card__action}}.

So no ancestor of the button supplies a family, {{inherit}} falls through to the root initial value, and Chrome computes {{Times}}. A live check at 1440px recorded exactly this: {{.app-link-button}} computed {{Times}} while its sibling {{a.govuk-link}} in the same {{<ul>}} computed {{"GDS Transport", arial, sans-serif}}.

h3. Why the other declarations are fine

{{font-size: inherit}}, {{font-weight: inherit}} and {{line-height: inherit}} do NOT conflict, because {{.govuk-link}} sets none of them; the button correctly inherits size 19 and bold from {{.govuk-summary-card__actions}} (the summary-card mixin sets {{govuk-font-size(19)}} and {{govuk-typography-weight-bold}}). {{font-family}} is the only broken declaration. The explicit {{color}} override at {{_main.scss:23}} is correct and load-bearing (govuk sets link colour via {{:link}}, which never matches {{<button>}}) and must stay.

h3. Blast radius — narrower than it looks

CORRECTED after implementation. There are four {{.app-link-button}} call sites, all of which also carry {{.govuk-link}}, but only the dashboard one was ever broken. {{font-family: inherit}} only falls through to the browser default where no ancestor supplies a family:

* {{features/dashboard/template.njk:98}} — inside {{.govuk-summary-card__actions}}, which sets font-size and font-weight but NO font-family. *Broken* — this is the reported defect.
* {{features/commodities/consignment-details/_selected-commodities-table.njk:8}} — rendered into a {{govukTable}} cell; {{.govuk-table}} sets {{font-family: GDS Transport, arial, sans-serif}}. Never broken.
* {{features/commodities/animal-identification/_identification-card.njk:19}} — inside {{.govuk-summary-list}}, which sets the same family. Never broken.
* {{features/documents/contracts/remove-action.js:12}} — rendered into a {{govukTable}} cell via {{documents/view-model/rows.js:27}}. Never broken.

The single stylesheet edit remains correct and safe for all four, but it only CHANGES the dashboard. A regression test on any of the other three passes identically before and after the fix, so none was added — one was written during implementation and removed for exactly that reason.

h3. Alternative ruled out

A wrapping/width theory — that the action row wraps because {{frontend:src/server/app/shared/layout.njk:57}} hard-codes {{govuk-grid-column-two-thirds}} where the pre-retrofit layout used {{govuk-grid-column-full}}. That width regression is real and worth its own ticket, but it is a whole-page layout change affecting every screen — it does not single out "Copy as new", and fixing it would leave the button still rendering in Times. The font-family conflict is the defect that makes this one element, and only this element, look wrong.

h2. Fix

h3. trade-imports-animals-frontend

* {{src/client/stylesheets/core/_main.scss}} — edit. Delete the {{font-family: inherit;}} declaration from the {{.app-link-button}} rule (line 16). Change nothing else in that rule: {{background}}, {{border}}, {{padding}}, {{cursor}}, {{font-size: inherit}}, {{font-weight: inherit}}, {{display: inline}}, {{vertical-align: baseline}}, {{line-height: inherit}}, the {{color}} declaration and the {{:hover}} / {{:active}} blocks all stay exactly as they are, as does the existing comment above {{color}}. With the reset gone, govuk-frontend's {{.govuk-link, a \{ font-family: GDS Transport, arial, sans-serif \}}} applies to the button; every call site pairs {{app-link-button}} with {{govuk-link}}, so no site loses its family. Do not add a replacement {{font-family}} and do not add any new custom CSS.
* {{src/server/app/sets/live-animals/journeys/linear/features/dashboard/dashboard.e2e.spec.js}} — edit. Add one test to the existing {{dashboard feature — notification rows and actions}} describe block that pins the link-button against its anchor sibling. Start a notification ({{startNotification(page)}}, {{journeyIdFromPage(page)}}, {{page.goto('/')}}) so a DRAFT row renders, then use the file's existing {{actionFor(page, role, action, reference)}} helper to get {{actionFor(page, 'button', 'Copy as new', reference)}} and {{actionFor(page, 'link', 'Delete', reference)}}. Assert with {{expect.poll}} on {{evaluate((el) => getComputedStyle(el).fontFamily)}} that the Copy as new button's computed {{fontFamily}} equals the Delete link's, and separately that it matches {{/GDS Transport/}}. Self-contained, raw locators, auto-waiting — no sleeps, no page objects, no new helper module.

h2. Acceptance criteria

* On the notification dashboard, the "Copy as new" action renders in the same typeface as the Resume, View and Delete actions in the same card — GDS Transport, not the browser default serif
* "Copy as new" is visually indistinguishable from its neighbouring actions in font family, size, weight, colour, underline and focus state; only the neighbours' anchor-vs-button semantics differ
* The "Amend" action on a submitted notification card, which is also a POST-backed link-button, renders in GDS Transport too
* The "Remove" link-buttons on the selected-commodities table, the animal-identification card and the documents list are UNAFFECTED — they already rendered in GDS Transport, inherited from their table or summary-list container, and must continue to
* "Copy as new" still POSTs and still creates a new draft — behaviour, CSRF crumb, idempotency key and copyOrigin are unchanged
* No new custom CSS class or declaration is introduced; the change only removes a declaration that was overriding the govuk-frontend link styles
* No new client-side JavaScript is introduced; the page behaves identically with JavaScript disabled
