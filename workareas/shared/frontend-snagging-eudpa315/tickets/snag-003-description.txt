h2. Snag as reported

Your commodities boxes at the task list page is ugly, bad text wrapping and doesn't have the styling from figma

h2. Diagnosis

The complaint is about the hub / task list page ("Overview", {{frontend:src/server/app/sets/live-animals/journeys/linear/features/hub/}}). The "Your commodities" block at {{frontend:src/server/app/sets/live-animals/journeys/linear/features/hub/template.njk:9-35}} renders the two totals as {{govukSummaryList(\{ card: \{ title: … \}, rows: \[\{ key, value \}\] \})}} — one row per box, the box's explanatory sentence in the summary-list KEY and the bare number in the VALUE.

That is the wrapping defect, and the mechanism is exact. {{govuk-frontend}}'s {{.govuk-summary-list__key}} is fixed at {{width: 30%}} above the tablet breakpoint ({{frontend:node_modules/govuk-frontend/dist/govuk/components/summary-list/_mixin.scss:86-92}}) — a viewport media query, not a container query, so it applies however narrow the container is. The container here is doubly narrowed: {{shared/layout.njk:57}} wraps all page content in {{govuk-grid-column-two-thirds}}, and {{template.njk:11-12}} / {{23}} then splits that again into two {{govuk-grid-column-one-half}} columns. At a 1280px desktop that leaves roughly 336px per box, ~294px inside {{.govuk-summary-card__content}} padding, so the 30% key cell is ~88px wide. Into that ~88px go the 42- and 43-character bold sentences "Total number of animals in this consignment" / "Total number of packages in this consignment" ({{copy/copy.en.js:6,8}}), which shred into eight-plus one- and two-word lines beside a single-digit value. That is the reported "bad text wrapping", and it is a genuine defect regardless of how the design question is answered.

The "doesn't have the styling from figma" half is confirmed against the design source. The Figma export at {{~/Desktop/design/02-notification-hub/notification-hub-(posh-tasklist).html:118-133}} renders each box as a bespoke {{.app-card}} div: {{<p class="app-card__number">8</p>}} then {{<p class="app-card__label">Animals</p>}} then {{<p class="app-card__desc">Total number of animals in this consignment</p>}}, stacked full-bleed, styled by inline CSS at lines 9-28 ({{background: #f3f2f1}}, {{padding: 20px}}, number {{#1d70b8}} / bold / {{2.25rem}} / {{line-height: 1}}, label {{#1d70b8}} / bold, desc {{#0b0c0c}}). Crucially the design's {{govuk-grid-row}} sits directly in {{govuk-main-wrapper}} at full page width (lines 108-118), not nested in a two-thirds column — so each design box is ~520px wide and its sentence fits on one line. There is nothing in the shipped repo resembling this: {{grep -rn "app-card\|stat-card" src}} returns nothing, and {{src/client/stylesheets/components/_index.scss}} registers only notification-list, notifications-pagination, task-list and service-header.

Why this is not simply actionable: the shipped {{govukSummaryList(\{card:…\})}} is not an accident, it is the documented execution of a ruling. {{workareas/journey-builder/EUDPA-249/figma-digest/journey-map.md:154}} lists the {{app-card}} tiles among "custom CSS outside the govuk-frontend toolbox" and states "The real build should map these to stock equivalents (accessible-autocomplete, govukSummaryCard, cdp-uploader, govukTaskList, govukWarningText)"; {{extract.figma.json:1259-1272}} and {{figma-digest/gap-register.md:68}} corroborate that these two tiles are the bespoke {{app-card}} component. {{.claude/rules/gds.md}} reinforces it ("Stay inside the govuk-frontend toolbox … no custom CSS"). Reproducing the Figma therefore reverses a recorded ruling and adds a bespoke SCSS partial — a design call, not a mechanical fix. It is also under-determined in a second, wider-blast-radius way: matching the Figma faithfully requires the block to escape {{shared/layout.njk:57}}'s {{govuk-grid-column-two-thirds}}, which is the shared layout every page in the journey renders through.

Test-coverage gap, which is part of the defect. Nothing exercises this block in a browser at all. {{frontend:.../hub/hub.e2e.spec.js}} never asserts the totals block, and its axe test at lines 104-120 runs against {{startNotification(page)}} — a fresh notification with no commodity lines, where {{buildCommodityTotals}} returns {{null}} ({{controller.js:142-151}}) and the block does not render. {{tests:tests/e2e/features/hub-groups-and-cya-rows.spec.ts}} likewise starts fresh and pins only the six group headings and six task lists. Only {{copy/copy.test.js:221-246}} covers the block, and purely as a view-model arithmetic check that never renders a pixel.

Constraint any fix must respect: {{tests:tests/e2e/features/hub-groups-and-cya-rows.spec.ts:8-15}} uses {{expect(getByRole('heading', \{level: 2\})).toContainText(\[six strings\])}}, which is count-exact. It passes today only because the fresh-notification hub has no "Your commodities" h2. Adding or re-levelling any h2 on the fresh hub turns it red.

h2. Fix

*trade-imports-animals-frontend*

* {{src/server/app/sets/live-animals/journeys/linear/features/hub/template.njk}} — EDIT. Replace the two half-column single-row {{govukSummaryList}} cards at lines 9-35. Both gate options stack number, then label, then the explanatory sentence — the sentence must never sit in a 30%-width summary-list key again. Leave the h2 at line 10 and the group h2s at line 38 at their current levels.
* {{src/client/stylesheets/components/_stat-card.scss}} — CREATE, OPTION A ONLY (gate answered "reproduce the Figma"). New bespoke tile partial mirroring {{~/Desktop/design/02-notification-hub/notification-hub-(posh-tasklist).html:9-28}} in govuk tokens: {{govuk-colour("light-grey")}} background, {{govuk-spacing(4)}} padding, number {{2.25rem}} / bold / {{govuk-colour("blue")}} / {{line-height: 1}}, bold blue label, black description. Do not reuse {{$app-light-grey}} — {{#f8f8f8}} is not {{#f3f2f1}}. Must pass {{npm run lint:scss}}.
* {{src/client/stylesheets/components/_index.scss}} — EDIT, OPTION A ONLY. Register the new partial alongside the existing notification-list / notifications-pagination / task-list entries at lines 3-5. An unregistered partial never reaches the bundle and the styles silently do not ship.

h2. Acceptance criteria

* On a notification with at least one commodity line, the hub shows a "Your commodities" block giving the total number of animals and the total number of packages across every commodity line.
* At a 1280x800 desktop viewport, every label and every explanatory sentence in the "Your commodities" block renders on no more than two lines — no text wraps into a narrow column beside its number.
* Each box reads top to bottom as number, then label, then explanatory sentence — the sentence is never rendered as a summary-list key beside the number.
* At a 360x740 mobile viewport the block still reads number-then-label-then-sentence, with no horizontal overflow of the page body.
* A notification with no commodity lines shows no "Your commodities" block at all (unchanged behaviour).
* The counts treat blank animal or package entries as zero and sum across all commodity lines (unchanged behaviour).
* Every heading on the hub keeps its current level and type size — a fresh notification still renders exactly six h2 task-group headings.
* The hub rendered with the totals block present has no serious or critical axe violations under wcag2a / wcag2aa.
* English and Welsh copy modules for the hub remain structurally identical.
* If the gate is answered "reproduce the Figma": the rendered tiles match {{~/Desktop/design/02-notification-hub/notification-hub-(posh-tasklist).html}} — number above the label, label bold in {{govuk-colour("blue")}}, sentence beneath in {{govuk-colour("black")}}, on a {{govuk-colour("light-grey")}} panel with {{govuk-spacing(4)}} padding — and the SCSS partial is registered in {{src/client/stylesheets/components/_index.scss}} so the styles reach the built bundle.

h2. Decision needed

The Figma stat tile is bespoke CSS (a {{.app-card}} grey panel with a {{2.25rem}} blue number above a bold blue label above a black sentence — {{~/Desktop/design/02-notification-hub/notification-hub-(posh-tasklist).html:9-28}}), and the EUDPA-249 design digest already ruled at {{workareas/journey-builder/EUDPA-249/figma-digest/journey-map.md:154}} that these bespoke {{app-card}} components "should be mapped to stock equivalents (… govukSummaryCard …)" — which is exactly what the shipped code does. So: do we reverse that ruling and reproduce the Figma tile with a new custom SCSS partial (option A), or keep the block inside the govuk-frontend toolbox and re-lay it out with stock components/utility classes so only the wrapping is fixed and it will still not look like the Figma (option B)?
